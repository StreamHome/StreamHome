# Initial Setup

For a managed installation, start the service and retrieve its private one-time
setup code from a controlling terminal:

```bash
sudo streamhome start
sudo streamhome bootstrap
```

`sudo streamhome setup-code` is an alias for the same code. Open the configured
web URL's `/setup` page. Existing checkout installations retain the setup URL/code
flow printed by their supported `./start.sh`.

Setup verifies the runtime, creates the administrator, optionally enables local
TOTP, validates TMDB access and selects local or Google Drive storage. Managed
public URL/port values come from the recorded deployment. Change them with
`sudo streamhome configure`, then reload setup; browser state cannot override them.

## Important behavior

- Setup credentials and passwords are not stored in browser checkpoints.
- A setup session lasts two hours.
- Optional TOTP enrollment is generated by the server, bound to the current setup session, and expires after 15 minutes. Scan the displayed QR code or use its manual setup key, then verify a six-digit code before continuing.
- An active Google Drive job can be rebound after the bootstrap code is entered again.
- TMDB validation produces a signed setup receipt; completion does not depend on a second TMDB network request.
- A committed setup finalization remains finalized even if the browser loses its response. Follow an explicit finalization-recovery instruction instead of repeating account creation.

## Local storage

Managed defaults are `/var/lib/streamhome/media` for local media and
`/var/lib/streamhome/database.db` for the catalog. Legacy checkouts retain their
`server/media` and `server/database.db` defaults. Application storage configuration
owns the actual media location; the installer does not relocate it.

## Google Drive

Follow [Google Drive Storage](google-drive.md). Rclone is controlled only by StreamHome through its encrypted application-owned configuration.

## Completion

Save the one-time MediaSender ingestion token and any TOTP recovery codes before leaving the completion page. Managed setup finalizes without scheduling a checkout restart. Legacy setup may
use its detached `restart.sh` lifecycle handoff.

Automatic updates can be enabled during setup and configured later under **Admin center → Updates**. The default policy waits for verified idle activity before a preflighted, health-gated restart.
